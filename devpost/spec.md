# Docket: техническа спецификация

## How This Works, In Plain Language
Docket има **две части**, които си говорят през интернет:

1. **Страницата (в браузъра).** HTML, CSS и JavaScript, хостнати безплатно на GitHub Pages. Всички потребители отварят един и същ адрес. Тя показва таблото, чата, формулярите и настройките. Пази **копие на задачите на устройството** и **опашка с промени**, които още не са изпратени, за да работи и без интернет. Малък помощник в браузъра, **service worker**, пази самите файлове на страницата, така че тя да се отваря и офлайн.
2. **Личният Apps Script на всеки потребител (в Google).** Работи като малък личен сървър: получава заявки от страницата, проверява **тайния код за достъп**, чете и пише в **Google таблицата** на потребителя (листове Tasks, Categories, Logs) и **вика Groq AI**. AI ключът стои скрит тук, никога в браузъра.

**Пример:** поставяте имейла и натискате „изпрати" → страницата праща текста и имената на активните колони към вашия Apps Script → той пита Groq и получава подредени задачи → връща предложението → виждате го в чата → потвърждавате → страницата веднага показва задачите и изпраща „добави тези задачи" към скрипта → скриптът ги записва в таблицата. На телефона следващото зареждане ги показва.

**Защо тази форма:** няма платен сървър (нулеви разходи), данните са в собствената ви таблица, а един адрес работи за всички. Офлайн режимът изисква страницата да е отделно от Apps Script, защото service worker не работи в страница, показана от Apps Script.

## The Core Journey Through the System
PRD ref: `prd.md > The Core Journey`.

1. **Първо отваряне** → страницата не намира настройки в паметта на устройството → показва Welcome (3 карти) → Настройка.
2. **Настройка** → инструкциите водят потребителя: създава Google таблица → Extensions → Apps Script → поставя кода от `apps-script/` → пуска функцията `setup()` веднъж (създава листовете и генерира код за достъп) → Deploy като Web app → копира URL-а. В приложението въвежда **Script URL**, **код за достъп** и **Groq ключ** → страницата праща `saveSettings` → скриптът запазва ключа в своите Script Properties → страницата пази в устройството само URL-а и кода, не ключа.
3. **Табло** → страницата праща `getAll` → скриптът връща активните и архивираните колони и задачите → страницата ги пази локално и ги рисува.
4. **Чат** → плаващ бутон → чат поле → текстът се изпраща с `propose` (текст + имена на активните колони + днешната дата + предишно предложение и корекция, ако има такива).
5. **Предложение** → скриптът вика Groq със схема → връща `{has_tasks, message, tasks[]}` → чатът показва задачите и колоните, като новите са отбелязани „нова".
6. **Корекция** → новото съобщение се праща пак с `propose`, заедно с предишното предложение → ново предложение. **Потвърждение** → страницата създава задачите (и новите колони) локално → слага ги в опашката → `applyChanges`.
7–9. **Работа със задачи** → всяка промяна (редакция, отметка, изтриване) се прилага веднага на екрана → след прозореца за undo влиза в опашката → `applyChanges`.
10. **Архивиране** → отметната е последната задача в колона → undo за около 5 секунди → операцията „архивирай колона" влиза в опашката.

## Stack
- **Страница:** HTML + CSS + JavaScript (ES модули), **без framework и без build стъпка**. *Избор на обучаемия:* приема JavaScript вместо Python, защото Apps Script е само на JS и офлайн режимът изисква страница в браузъра. Цена: целият код на приложението е JS.
  - Офлайн: [Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) + [Web App Manifest](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest) (инсталиране на началния екран).
  - Локално копие и опашка: [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) (достатъчно за лични задачи; по-просто от IndexedDB).
- **Бекенд:** [Google Apps Script](https://developers.google.com/apps-script) уеб приложение ([Web Apps](https://developers.google.com/apps-script/guides/web)), [SpreadsheetApp](https://developers.google.com/apps-script/reference/spreadsheet), [UrlFetchApp](https://developers.google.com/apps-script/reference/url-fetch) за Groq, [PropertiesService](https://developers.google.com/apps-script/reference/properties) за ключа и кода.
- **AI:** [Groq](https://console.groq.com/docs/overview), модел **`openai/gpt-oss-20b`** със [Structured Outputs](https://console.groq.com/docs/structured-outputs) `strict: true` (JSON, гарантирано по схемата). Препоръка, приета от обучаемия. `openai/gpt-oss-120b` е възможна резервна опция за следващия етап.
- **Python** — не в приложението. За следващия етап: скрипт за анализ на листа Logs за тезата.

**Да се провери в началото на изграждането:** (1) безплатните лимити на Groq за `gpt-oss-20b` (страницата с моделите не ги описва); (2) че `fetch` POST към Apps Script `/exec` с `Content-Type: text/plain` работи от GitHub Pages (Apps Script пренасочва към `script.googleusercontent.com`; този подход е широко използван, но трябва да се потвърди).

## Where It Runs and How Someone Tries It
- **Локално по време на изграждането:** от папката на проекта
  ```bash
  python3 -m http.server 8000
  ```
  после се отваря `http://localhost:8000`. Service worker работи на localhost. Apps Script трябва да е deploy-нат, а неговият URL да е въведен в настройките.
- **Публично (избор на обучаемия):** GitHub Pages от корена на публичното хранилище → `https://<потребител>.github.io/<repo>/`. Отваря се от телефон и лаптоп; на телефона може „Добави към началния екран".
- **Нужно:** Google акаунт (таблица + Apps Script), Groq API ключ ([console.groq.com/keys](https://console.groq.com/keys)), GitHub акаунт за Pages.
- **За демо видеото:** празно табло → поставяне на имейла за откриването → предложение → корекция → потвърждение → 4 задачи в „15 септември" → отваряне, отметка → последна отметка → undo → архив. Бонус: изключване на мрежата → лента „Няма връзка" → ръчна задача → включване → синхронизация.
- Изисква се и публично GitHub хранилище; деплойът не замества видеото.

## Look and Feel
От `prd.md > Look and Feel`. Посока: фабричните приложения на Apple, семпло и спокойно.
- **Шрифт:** системният (`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Roboto, sans-serif`), с ясна йерархия: голямо удебелено заглавие на колоната, нормален текст на картичката, малък сив текст за срок и мета данни.
- **Цветове:** неутрални сиви повърхности + **един акцентен цвят** (системно синьо). Приоритетът е малка цветна точка, без големи цветни етикети. Срокът: „просрочено" е червено, „днес/утре" оранжево, другото сиво.
- **Тема:** CSS променливи за светла и тъмна; изборът „светла / тъмна / системна" се пази на устройството.
- **Повърхности:** картички със заоблени ъгли и много лек сянка; плаващият бутон и чатът са полупрозрачни със замъгляване (`backdrop-filter`), като листовете в iOS.
- **Движение:** кратки, плавни „spring" преходи (разширяване на бутона в чат, падане на отметнатата задача надолу); уважава `prefers-reduced-motion`.
- **Телефон:** колоните се плъзгат хоризонтално с „щракване" (`scroll-snap`), всяка е около 85% от ширината. На лаптопа колоните са една до друга.
- **Текстове в интерфейса:** кратки, на български, спокоен тон.
- По време на изграждането се ползва наличният skill за дизайн в стил Apple.

## Components

### Страница: Обвивка и навигация (`js/app.js`)
Стартира приложението, решава кой екран да покаже (Welcome → Настройка → Табло), отваря менюто (Архивирани, Настройки).
PRD ref: `prd.md > Screens and Layout`.

### Страница: Welcome и Настройка (`js/settings.js`)
3 карти; инструкции стъпка по стъпка; полета за URL, код и Groq ключ; проверка на връзката (`ping`); избор на тема.
PRD ref: `prd.md > Настройка за всеки потребител`, `prd.md > Look and Feel`.

### Страница: Табло (`js/board.js`)
Рисува активните колони и картичките; свършените задачи са най-долу, бледи и задраскани; празно състояние с подкана.
PRD ref: `prd.md > Задачите в таблото`.

### Страница: Отворена задача и ръчен формуляр (`js/task.js`)
Детайли, оригинален откъс, редакция на място, отметка/размаркиране, изтриване. Същият изглед в режим „нова" е ръчният формуляр; категорията се избира само от активните колони.
PRD ref: `prd.md > Задачите в таблото`, `prd.md > Ръчно добавяне на задача`.

### Страница: Чат и предложение (`js/chat.js`)
Плаващ бутон → чат; изпраща `propose`; показва предложението (етикет „нова" за новите колони); корекции; потвърждение; връзка „+ ръчно". Офлайн е изключен и показва само ръчното добавяне. При грешка текстът остава в полето.
PRD ref: `prd.md > Въвеждане и AI предложение`, `prd.md > Правило за категориите (ядрото)`.

### Страница: Undo (`js/undo.js`)
Лента „Отмени" за около 5 секунди. Изтриване, отметка на последна задача (→ архив) и архивиране изчакват прозореца, преди да влязат в опашката.
PRD ref: `prd.md > Автоматично архивиране`, `prd.md > Задачите в таблото`.

### Страница: Локално хранилище и опашка (`js/store.js`)
Пази в localStorage последното копие на данните, опашката от неизпратени операции, настройките (URL, код) и темата. Всяка промяна първо се записва тук.
PRD ref: `prd.md > Работа без интернет`, `prd.md > States and Boundaries`.

### Страница: Синхронизация и конфликти (`js/sync.js`)
Следи `online`/`offline`; показва лентата „Няма връзка"; изпраща опашката с `applyChanges`, когато има връзка; обработва върнатите конфликти чрез диалог „двете версии → избери".
PRD ref: `prd.md > Работа без интернет`.

### Страница: Връзка с Apps Script (`js/api.js`)
Единствено място, което прави `fetch`. Добавя кода за достъп, мери времето, превежда грешките в кратки съобщения.

### Страница: Дати (`js/dates.js`)
Относителен срок („днес", „утре", „след 3 дни", „просрочено") и цветовото ниво.
PRD ref: `prd.md > Задачите в таблото`.

### Страница: Офлайн обвивка (`sw.js`, `manifest.webmanifest`)
Service worker кешира файловете на страницата (HTML, CSS, JS, икони), за да се отваря офлайн. Заявките към Apps Script **не** се кешират от него; за тях отговаря опашката.
PRD ref: `prd.md > Работа без интернет`, `prd.md > Достъп от всяко устройство`.

### Apps Script: Рутер и сигурност (`apps-script/Code.gs`)
`doPost(e)` чете JSON `{token, action, payload}`, сравнява `token` с `ACCESS_TOKEN` от Script Properties, вика правилното действие, връща JSON. `setup()` създава листовете със заглавни редове и генерира код за достъп (показва го в логовете на редактора).

### Apps Script: Данни (`apps-script/Data.gs`)
Чете и пише Tasks и Categories; прилага операции с проверка на версия (виж *Data Model*); връща конфликти.
PRD ref: `prd.md > Задачите в таблото`, `prd.md > Автоматично архивиране`.

### Apps Script: AI (`apps-script/Ai.gs`)
Съставя подканата, вика Groq със схемата, връща предложението. Кратки отговори (ниско `max_completion_tokens`, ниска температура).
PRD ref: `prd.md > Въвеждане и AI предложение`, `prd.md > Правило за категориите (ядрото)`.

### Apps Script: Логове (`apps-script/Logs.gs`)
Добавя по един кратък ред в листа Logs на заявка. Пазят се **всички** редове (избор на обучаемия).
PRD ref: `prd.md > Логове (заготовка за тезата)`.

## Data Model

### Лист `Categories`
| поле | значение |
|---|---|
| `id` | уникален код (UUID, създаден от страницата) |
| `name` | „15 септември" |
| `status` | `active` / `archived` |
| `created_at`, `archived_at` | ISO време |
| `updated_at` | ISO време на последната промяна |
| `version` | цяло число, +1 при всяка промяна |

### Лист `Tasks`
| поле | значение |
|---|---|
| `id` | UUID |
| `category_id` | към Categories |
| `title`, `details` | текст |
| `priority` | `high` / `medium` / `low` |
| `due_date` | `YYYY-MM-DD` или празно („без срок") |
| `source_excerpt` | кратък откъс от оригиналния текст |
| `origin` | `ai` / `manual` |
| `done` | `TRUE`/`FALSE`; `done_at` — ISO време |
| `created_at`, `updated_at` | ISO време |
| `version` | цяло число |

Изтриването премахва реда (след прозореца за undo).

### Лист `Logs` (един ред на заявка, без оригиналния текст)
`ts, request_id, action, model, ms, ok, error_code, tokens_in, tokens_out, tasks_proposed, tasks_confirmed, correction_round, corrected_fields, origin`
- `corrected_fields`: кои полета са се променили между първото предложение и потвърденото, например `category,due_date`. Това е суровината за **точност по полета** в тезата.
- Размер: около 14 клетки на ред; лимитът на Google Sheets (10 милиона клетки) стига за стотици хиляди заявки.

### Script Properties (в Apps Script, скрити)
`GROQ_API_KEY`, `ACCESS_TOKEN`, `GROQ_MODEL` (по подразбиране `openai/gpt-oss-20b`).

### На устройството (localStorage)
- `docket.settings` — Script URL и код за достъп (**не** Groq ключа).
- `docket.theme` — `light` / `dark` / `system`.
- `docket.snapshot` — последното копие на колоните и задачите с техните `version`.
- `docket.outbox` — списък с неизпратени операции.
- `docket.onboarded` — дали Welcome е видян.

**Когато потребителят излезе и се върне:** страницата веднага показва `snapshot` (работи и офлайн), после, ако има връзка, изпраща опашката и тегли `getAll`, за да се обнови.

### Как се засича конфликтът
Всяка операция в опашката носи `base_version`, тоест версията на задачата, която устройството е видяло, когато е направило промяната. Скриптът сравнява:
- `base_version == version в таблицата` → прилага промяната, `version + 1`.
- `base_version < version в таблицата` → някой друг (другото устройство) е променил задачата междувременно → **конфликт**: скриптът не прилага промяната и връща двете версии → страницата показва „Твоята версия / Версията от другото устройство" → избраната се изпраща отново с текущата версия.

## External Services and Dependencies

### Apps Script уеб приложение (наш собствен „API")
- **Deploy:** Execute as *Me*, Who has access *Anyone*. Защитата е кодът за достъп.
- **Заявка:** `POST <Script URL>` с `Content-Type: text/plain;charset=utf-8` (избягва допълнителна CORS проверка), тяло JSON:
  `{ "token": "...", "action": "...", "payload": { ... } }`
- **Отговор:** `{ "ok": true, "data": {...} }` или `{ "ok": false, "error": "code", "message": "..." }`
- **Действия:**
  - `ping` → `{ ok }`. Проверка на URL и код.
  - `saveSettings` `{ groq_api_key }` → запазва ключа.
  - `getAll` → `{ categories[], tasks[] }`
  - `propose` `{ text, active_categories[], today, previous_proposal?, correction? }` → `{ has_tasks, message, tasks[] }`
  - `applyChanges` `{ ops[] }`, всяка `{ op_id, type, entity, id, base_version, fields }` → `{ applied[], conflicts[{ id, server_record, your_fields }] }`
    - типове: `create`, `update`, `delete`, `archiveCategory`, `reactivateCategory`
  - `logEvent` `{ ... }` → записва ред (напр. потвърждение с `corrected_fields`).
- Документация: [Web Apps](https://developers.google.com/apps-script/guides/web), [ContentService](https://developers.google.com/apps-script/guides/content). Квоти: [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas).

### Groq Chat Completions
- `POST https://api.groq.com/openai/v1/chat/completions`, заглавка `Authorization: Bearer <GROQ_API_KEY>` (вика се само от Apps Script).
- Тяло (накратко): `model: "openai/gpt-oss-20b"`, `messages` (системна подкана + текст), `temperature: 0.2`, ниско `max_completion_tokens`, `response_format: { type: "json_schema", json_schema: { name: "docket_proposal", strict: true, schema } }`.
- Схема: `{ has_tasks: boolean, message: string, tasks: [{ title, details, category, is_new_category, priority: enum(high|medium|low), due_date: string|null, source_excerpt }] }`.
- Системната подкана включва: днешната дата, списъка с активните колони, правилото „предпочети съществуваща колона, иначе нова", „никога архивирани", „ако няма задача → `has_tasks: false` и кратко `message`", „без срок → `due_date: null`", отговори на български.
- Документация: [Structured Outputs](https://console.groq.com/docs/structured-outputs), [Models](https://console.groq.com/docs/models), ключове: [console.groq.com/keys](https://console.groq.com/keys). **Безплатните лимити да се проверят в началото на изграждането.**

## Important Failure Modes
- **Няма интернет** → лента „Няма връзка"; таблото от копието; чатът е изключен; ръчните промени влизат в опашката и се изпращат при връзка.
- **Groq е недостъпен, бавен или лимитиран (429)** → „AI не отговаря, опитай пак"; текстът остава в полето; логва се `error_code`.
- **Грешен Script URL или код** → `ping` при настройката се проваля → „Не мога да се свържа със скрипта. Провери URL-а и кода." → остава на екрана Настройка.
- **Конфликт при синхронизация** → диалог с двете версии; нищо не се губи незабелязано.

## What Was Simplified and Why
- **localStorage** вместо IndexedDB — данните на един човек са малки, а localStorage е много по-прост за четене и дебъгване. По-пълната версия би използвала IndexedDB за големи обеми.
- **Един модел (`gpt-oss-20b`), без fallback верига** — веригата и локалният алгоритъм са в следващия етап (`prd.md > Deferred From the POC`).
- **Без framework и без build стъпка** — по-малко за научаване и настройка; кодът се чете директно.
- **Ключът се въвежда в приложението веднъж и се праща към скрипта**, вместо ръчно в редактора на Apps Script — по-лесна настройка за другите хора; ключът не остава в браузъра.
- **Конфликтите се засичат само на ниво задача/колона** (версия на целия запис), не поле по поле — по-просто, а диалогът „избери версия" покрива нуждата.

### Решения на обучаемия
- **Архитектура:** JavaScript страница на GitHub Pages + личен Apps Script + Google Sheets; Python за анализ на логовете в следващия етап. *Приета препоръка.*

- **Логове:** един кратък ред на заявка с предложените полета, без оригиналния текст; **пазят се всички редове**.

### Решения, изведени от тях (детайли по изпълнението)
- `Content-Type: text/plain` към Apps Script; UUID-та от страницата (за да работи създаването офлайн); `version` + `base_version` за конфликти; около 5 секунди прозорец за undo.
- Часовата зона: страницата праща `today` от устройството; `appsscript.json` е с `Europe/Sofia` *(предположение)*.

### Неясното, което изяснихме
Обучаемият поиска обяснение как service worker-ът пази приложението офлайн, как страницата „говори" с Apps Script, как се засича конфликтът и как ще работим заедно по кода. Изяснено с обяснения по време на интервюто (виж *How This Works*, *Data Model > Как се засича конфликтът*, *External Services*). **Проверка по време на изграждането:** обучаемият изключва мрежата на телефона и вижда, че таблото се отваря и промените се изпращат след включване; на две устройства предизвиква конфликт и вижда диалога.
